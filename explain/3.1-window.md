# Task 3.1 – Window, image buffer and `put_pixel`

File: `src/render/window.c`. New fields in `t_game`: `mlx`, `win`, `img` (a `t_img`: `ptr`, `addr`, `bpp`, `line_len`, `endian`). Constants `WIN_W` = 1280 and `WIN_H` = 720 in `cub3d.h`.

## `init_window(game)`
Called from `main` after the parsing is done and the player view is set (a bad map never opens a window).
1. `mlx_init` → connection to the X server. Fails (no display) → `cannot connect to the display`.
2. `mlx_new_window(WIN_W, WIN_H, "cub3D")`.
3. `mlx_new_image(WIN_W, WIN_H)`: the off-screen buffer we draw into.
4. `mlx_get_data_addr` gives the raw pixel buffer plus `bpp` (bits per pixel, 32 on our setup), `line_len` (bytes per row, can be larger than `WIN_W * 4`) and `endian`.
Each failure prints an error and returns `1`; whatever was already created is released by `free_game`.

## `put_pixel(img, x, y, color)`
Ignores any `(x, y)` outside `0..WIN_W-1` / `0..WIN_H-1`, so later code cannot write outside the buffer. Otherwise it writes `color` (`0xRRGGBB`, the same packing as the floor/ceiling ints) at `addr + y * line_len + x * (bpp / 8)`. Drawing into an image and pushing it once per frame is much faster than `mlx_pixel_put`.

## `destroy_window(game)`
Destroys the image, the window, then the display (`mlx_destroy_display`) and frees `mlx`; each step only if it exists, then sets the pointers to `NULL`. `free_game` calls it first, so every error path (and the normal exit) releases the MiniLibX resources. Task 3.3 adds the ESC / red-cross handlers and the loop that call the same cleanup.

`main` does not call `mlx_loop` yet (3.3 adds it together with the exit events, otherwise the window could not be closed).
