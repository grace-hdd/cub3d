# Task 3.3 – Clean exit: ESC and the red cross

File: `src/render/events.c`. `main` now ends with `run_game(&game); free_game(&game);`.

## `run_game(game)`
1. `mlx_hook(win, 2, 1L << 0, key_press, game)`: X event 2 = KeyPress.
2. `mlx_hook(win, 17, 0, close_game, game)`: X event 17 = DestroyNotify, sent when the window is closed with the red cross.
3. `mlx_put_image_to_window` shows the image buffer once (still black until task 3.2 draws the floor and ceiling).
4. `mlx_loop`: waits for events until `mlx_loop_end` is called.

## `key_press(keycode, game)` / `close_game(game)`
`key_press` calls `close_game` when the key is ESC (`KEY_ESC` = 65307). `close_game` only calls `mlx_loop_end(game->mlx)`. It does not free or `exit()` anything: the loop returns to `main`, and `main` calls `free_game`, which destroys the image, the window and the display and frees the parsed data (`destroy_window` from 3.1). So ESC, the red cross and the error paths all end in the same cleanup.

## Makefile
`CFLAGS` now has `-std=gnu17`. `mlx_hook` takes `int (*)()`; with the compiler's default (C23) `()` means "no arguments" and our handlers (which have arguments) are rejected. MiniLibX itself is already built with `gnu17` for the same reason. `tests/run_parsing.sh` uses the same flag.

## Tests
`tests/test_exit.c` (needs a display, built with ASan + UBSan): it queues a fake ESC key (after an unrelated `a` key, which must be ignored) and then a fake DestroyNotify with `XPutBackEvent`, runs the real `run_game`, and then `free_game`. Both runs return from the loop with no error and no leak (leak detection confirmed working here with a deliberate leak).
