# Task 1.4 – Parse `F` and `C`

Files: `src/parsing/parse_color.c`, `src/parsing/parse_utils.c` (`is_space`, shared with 1.3).

## `parse_color(line, game)`
Handles one line. Returns `0` = color stored, `1` = error (message already printed), `-1` = not a color line.

1. The line must start with `F` or `C`, followed by a space/tab or the end of the line. So `Fx 1,2,3` is not a color line.
2. `F` writes to `cfg.floor`, `C` to `cfg.ceiling`. Both start at `-1` (`init_game`). A valid color is at most `0xFFFFFF`, so `-1` is a safe "not set" marker. If it is already set → `duplicate color identifier`.
3. `parse_rgb` reads `R,G,B` and packs it as `(r << 16) | (g << 8) | b`.

## `parse_value`
Skips spaces, then requires **1 to 3 digits**, converts with `ft_atoi`, and requires `0..255`. Skips spaces after the number.
- The 3-digit limit stops `ft_atoi` from overflowing: `4294967296` would wrap to `0` and be accepted. `007` is allowed, `0000` is rejected.
- No sign is accepted (`-1` and `+1` fail on the digit check).

After the third value only spaces may remain. Anything else (`1,2,3,4`, `1,2,3x`) → `invalid color`. The color is written only when the whole line is valid.

## Wiring
`parse_textures` (temporary driver) calls `parse_color` for every line that `parse_texture` did not take (`-1`). Task 1.5 will replace the driver. `parse_color.c` and `parse_utils.c` are in the Makefile `SRCS`.
